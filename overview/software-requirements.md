# Software Requirements

ความต้องการของระบบสรุปจากฟีเจอร์ในหน้าจอแอปและ User Flow ของแต่ละกลุ่มผู้ใช้

## Functional Requirements

### Sender

* สร้างรายการส่งพัสดุ ระบุขนาด (กว้าง × สูง × ลึก) น้ำหนัก จำนวน และประเภทพัสดุ
* ถ่ายรูปหรืออัปโหลดรูปพัสดุ (บังคับก่อนดำเนินการต่อ)
* ระบุว่าเป็นสินค้าแตกง่าย/เปราะบาง เพื่อแสดงคำเตือนให้ผู้ขับ
* ดูราคาประเมิน ยืนยันและชำระเงิน (บัตร หรือ QR PromptPay)
* จองส่งพัสดุล่วงหน้า เลือกวันและช่วงเวลารับพัสดุ
* ติดตามสถานะและตำแหน่งผู้ขับบนแผนที่พร้อม ETA
* แชทหรือโทรหาผู้ขับ
* ดูประวัติการส่งและการจอง ยกเลิกการจองได้
* ใช้ AI Support Chatbot

### Driver

* รับการแจ้งเตือนงานและกดรับงาน
* ดูงานที่กำลังจะส่ง และนำทางไปจุดรับและจุดส่ง
* แชทกับผู้ส่ง และแจ้งปัญหาระหว่างทาง
* ให้ผู้รับเซ็นชื่อยืนยันรับพัสดุ
* ดูประวัติงาน สรุปรายได้ และโปรไฟล์

### Admin

* ล็อกอินผ่านเครือข่ายบริษัท
* ดู Dashboard จำนวนออเดอร์และรายได้
* ตรวจเอกสาร KYC ของผู้ขับก่อนอนุมัติ
* ดูสถานะการจัดส่งทั้งหมด
* จัดการเคสใน AI Escalation Inbox และ ticket ตาม SLA

## Non-functional Requirements

| ด้าน | เป้าหมาย |
| --- | --- |
| Capacity | รองรับผู้ส่ง 40,000 คนต่อวัน และงาน 80,000 งานต่อวัน |
| Availability | ไม่มี Single Point of Failure บน customer request path (Multi-AZ บน AWS) |
| Latency | ทุก request ของลูกค้าอยู่ใน AWS Region เดียว ไม่ข้ามไปยัง Private Datacenter แบบ synchronous |
| Data retention | เก็บข้อมูลธุรกรรมหลัก 5 ปี แชท 30 วัน |
| Security | ยืนยันตัวตนด้วย Cognito (JWT), WAF + Shield ที่ Edge และ KYC ของผู้ขับเก็บใน on-prem |
